## 2. 产品是什么（给新会话的心智模型）

### 2.1 三个入口，一个内核

| 层 | 定位 | 说明 |
|---|---|---|
| 入口 A：粘贴检查 | **主战场** | 商家把已有文案贴进来检查（高频动作，一天 5–10 次） |
| 入口 B：从零生成 | 获客/体验 | 给没文案的人用；生成结果**必须经过自检 + 自动改写**才展示（ADR-003） |
| 内核 | 检索 → 检查 → 引用条款 → 逐条改写 → 人工确认 | 价值与护城河；**不是"多生成 10 版"** |

### 2.2 四条不能碰的铁律

1. **页面上的每个数字都必须来自后端**（`usage` / 历史条数 / 违规条数），不许写死、不许估（ADR-008）。
2. **改动条数 = 违规条数**，编号 ①②③ 三栏共用；改不了的逐条标「未自动改写」，**不编造**（ADR-009）。
3. **每条违规必须能指回原句 + 条款原文**（`clause` 来自 `rules.csv` 的 `quote`，后端逐字校验）。
4. **不展示无法定位的结论**：不再有「复检另有 N 处命中，需人工确认」这类没有落点的提示（ADR-009 修订）。

> 已知张力（P2，未改）：状态条/首页的「规则库 40 条」仍是前端常量 `RULE_COUNT`，不是接口返回值。
> 规则冻结期间无影响；一旦扩规则，必须改成从 `/health` 或 `/api/rules` 取（见 §8）。

### 2.3 用户原话（理解产品的最好材料，都在 `docs/log.md`）

- 「我们不可以因为有修改功能，就给用户专门挖坑……生成的东西就要一步到位。」
- 「系统只检查出 2 个问题，但是改的时候有三个问题蹦出来，这肯定是不科学的。」
- 「检查出来的就是确定有问题的，不要弄模棱两可的东西出来。」
- 「只要查过都要算在历史记录里，但是一定不要弄混了，每个人只能看到自己的记录。」

### 2.4 替代方案与差异

| 方案 | 能给什么 | 缺什么 |
|---|---|---|
| 人工自查 / 平台提示 | 有判断，但依赖经验 | 不说哪句、哪条；不可追溯 |
| 词表类工具 | 命中敏感词 | 只给词，不给条款和改写；语境误报多 |
| 通用大模型 | 能写能改 | 结论不稳定、不能对账、不可回放 |

差异：**每条判断指回原句与条款，改动能对账**。

### 3.2 一次 analyze 的真实数据流（页面唯一入口）

```
POST /api/analyze  {content 或 draft_id}
  ├─ get_owner：读 X-Owner-Id（没有就落 "public" 桶）
  ├─ _resolve_and_check：建/取 draft（带 owner_id）→ check_text #1 → 写 checks 表
  ├─ check_text #2（独立样本）→ merge_check_results（去重 + 按原文位置排序）
  ├─ rewrite_draft(verify=False)：逐条替换 → changes（1:1，带 start/end）
  ├─ log_usage：一行 llm_usage 日志（tokens/耗时/attempts/owner）
  ├─ 写 events：kind=check，payload=完整响应快照（点开历史可恢复）
  └─ 返回 AnalyzeResponse
```

**注意**：`/api/check` 只检查（评测/外部接口用），页面**不再调用**；`/api/rewrite` 仍保留（带复检，给外部用），页面也不调用。

| `app/workbench/page.jsx` | 三栏工作台：**只渲染 sessionStorage 里的 analyze 结果**，不发改写请求 |
| `app/history/page.jsx` | 历史列表（标题/问题数/状态/时间，点击恢复） |
| `app/drafts/page.jsx` | 生成后的选稿页 |
| `app/rules/page.jsx` | 规则库（优先读真接口，后端没起才退回样例） |
| `components/TopBar.jsx` | 顶栏；含「规则库」入口（规则页自身隐藏） |
| `components/StatusBar.jsx` | 「规则库 N 条」（可点）+ 真实 tokens/耗时；没有就整段不显示 |

### 3.4 数据模型（6 张表）

- `products` → `drafts`（`owner_id` 可空，老数据为空）
- `checks`：每次检查的违规明细（`verdict` = violation / uncertain / suspected）
- `confirmations`：确认记录，`UNIQUE(draft_id)` 保证幂等
- `events`：**历史的主表**（方案 C）；`owner_id / kind / draft_id / title / violation_count / remaining_count / status / payload / created_at`
- `rules`：`rules.csv` 的副本，init 时重建

### 3.5 关键不变量（写新代码时必须守住）

1. `len(violations) == len(rewrite.changes)`，且 `n` 一一对应。
2. 每条 violation 的 `quote` 必须逐字出现在原文里（后端已校验）。
3. 每条 violation 必须带 `clause`（条款原文）和 `source_url`。
4. `rewrite.changes[i].start/end` 切出来的文本 == `changes[i].after`（除 `unresolved`）。
5. 页面上的 tokens / 耗时 / 条数只能来自接口，不能有默认值兜底。
6. 所有读写按 `owner_id` 过滤；越权一律 404，不暴露存在性。

## 5. 评测（本项目的"证据"部分）

### 5.1 为什么做

没有评测就只能盲改；漏报分布决定补哪条规则；面试时"你怎么证明它准"要有话可说。**不是为了在简历上写一个漂亮的百分比**——24 条自建样本必须标注局限。

### 5.2 样本与 gold

- **24 条真实小红书带货笔记**（001 + 002–024），覆盖化妆品、母婴、食品、养生/保健、服饰、家居、办公、首饰。
- 三层：`main`（主指标）/ `smoke`（冒烟，太容易）/ `edge`（拿不准，单独分析）。本次全部 24 条进 main，24 处句子进边界项。
- **gold 流程**：AI 按 `rules.csv` 预标注（rule_id + quote + 依据 + 反例）→ 作者逐条「同意 / 不同意 + 理由 / 拿不准」→ 只有一致项进 gold。
- 作者认为有问题、但 40 条规则里找不到可挂条款的 **4 处**，记为**规则缺口**，不硬套（§5.5）。
- 分布：**8 处 gold / 4 处规则缺口 / 24 处边界 / 39 处反例**。

### 5.3 指标口径

| 指标 | 定义 |
|---|---|
| 严格召回 | 命中处数 ÷ gold 处数；命中 = `rule_id` 严格相等 **且** `quote` 归一化后相等/互相包含 |
| 提示召回 | gold 是否被提到过（`violations` 或 `uncertain`，同句或同规则） |
| 误报率 | （报出 − 命中 − 边界命中）÷（报出 − 边界命中） |
| 引用正确率 | `quote` 在原文逐字出现 ∧ `rule_id` 存在 ∧ `clause` 与 `rules.csv` 一致 |

补充：一次 `analyze` 做**两遍独立检查取并集**；`uncertain`（confidence < 0.7）不计入严格召回，单独看「灰区」；边界项需要资质/语境，报了不算误报、不报也不算漏。

### 5.4 当前结果（v1.1，2026-10-27）

| 指标 | 值 | 分子 / 分母 |
|---|---|---|
| 严格召回 | **6/8（75%）** | 6 / 8 |
| 提示召回 | **7/8（87.5%）** | 7 / 8 |
| 误报率 | **4/10（40%）** | 4 / 10 |
| 精确率 | **6/10（60%）** | 6 / 10 |
| 引用正确率 | **18/18（100%）** | 18 / 18 |

**v1 → v1.1 做了什么**：只改 `backend/app/prompts.py` 的判定纪律（规则 40 条、样本 24 条不动）：
B 加适用性承诺例外；G `FLM-007` 不覆盖泛称；H `PLT-018` 不覆盖配料/参数；I `ABS-005` 不覆盖体感；
J 区分第一人称体验与商品功效承诺；K 痛点 ≠ 疾病治疗；L 方剂名 → `FLM-002`；M `PLT-002` 扩到入团/预约/领券。
完整过程见 `eval/report-v1.md` §8（含 v1 基线）。

### 5.5 仍然存在的问题

**漏报 2 处**：
- 014「五苓伏湿膏」：同类方剂名纪律对 015 生效、对 014 不生效（模型不一致）。
- 017「眼睛没那么容易酸涩疲劳」：检索没召回 `FLM-003`，模型改挂 `FLM-009`（同句错规则，严格口径记一漏一误）。

**误报 4 处**：002「一整天不脱妆」、004「最强手法」、013「啃咬也放心」、017（同句错规则）。

**规则缺口 4 处**（作者判违规、但无条款可挂）：
| 样本 | 原句 | 缺什么 |
|---|---|---|
| 007 | 全进口的纱线 | 产地/原料来源的举证要求 |
| 010 | 丹麦宝宝都在用 | 虚假人气/使用人数宣称 |
| 012 | 生物基双恒温隔绝湿冷 | 无出处的技术表述 |
| 013 | 以母婴级标准 | 无国家/行业依据的等级宣称 |

> 这 4 条是 v2 规则扩容的直接清单；不要拍脑袋补规则，先按缺口补，再跑同一批 24 条回归。

### 5.6 局限（必须一起读）

- 24 条、8 处 gold、10 条计分报出：分母是个位数，只能说明方向，不能当"平台准确率"。
- 单模型、单 prompt、单次运行；没有跑第二遍，稳定性未知。
- v1.1 是在这 24 条上做错误分析后改的，有"对着这批题改"的风险。
- gold 不是法律意见；"什么算主观体验"仍有判断空间。
- 只测文本，不测图片/视频/账号级规则。


**注意**：本机 8000/8010 可能被旧 uvicorn 占着，起服务前先 `lsof -nP -iTCP:<port> -sTCP:LISTEN`。

### 6.5 HTTPS（唯一挂着的部署项）

- 不紧急：域名只影响"链接观感"，不影响功能。
- 三条路：① 公网 IP 证书（Let's Encrypt 2026 起支持，短期 6 天、必须自动续期）；② 域名 + ICP 备案（1–3 周）；③ 换香港轻量服务器（免备案）。
- 用户已决定：**暂不做**，先补评测和 PRD。
- 若以后做：Nginx 加 `listen 443 ssl` + 80 → 301；前端不用改（同源相对路径 `/api`）。

## 10. 坑（踩过的，按"会不会再踩"排序）

| 坑 | 位置 | 说明 |
|---|---|---|
| **Pydantic `response_model` 会裁掉没声明的字段** | `schemas.py` + `api.py` | 业务层算好了 `usage`/`clause`，schema 没声明 → 接口就是不返回。加字段必须两边改 |
| **Hook 不能在提前 return 之后** | `app/workbench/page.jsx` | 曾把 `useMemo` 写在 `if (!sample) return null` 后面 → React error #310 整页报错 |
| **mock 与后端字段名不一致 → 白屏** | `lib/api.js` | mock 用 `text`、后端用 `script`；必须在数据层归一化（ADR-006） |
| **`next build` 会清空 `out/`** | — | 临时 seed 页要在构建**之后**生成；部署脚本会用真接口重新构建 |
| **粘贴文案的"标题"= 正文第一行** | `api.py` `_resolve_and_check` | 若同时当 title 传给检查器，同一句会查两遍；粘贴场景统一 `title=""` |
| **"改写后的复检"不能当结论** | `rewrite.py` / `api.py` | 它命中的句子可能在改写文里，指不回原句；已改为原文双检 + 逐条标注（ADR-009 修订） |
| **Nginx 429 默认是 HTML** | `nginx-content-guard.conf` | 前端 `JSON.parse` 会炸；已让 429 返回 JSON，前端也加了兜底 |
| **deploy 同步 `data/` 只排除 `*.db`** | `scripts/deploy.sh` | 会覆盖线上 `-wal/-shm`；已加 `--exclude '*.db-*'` |
| **测试脚本自己会骗人** | — | 测备份保留策略时先 `touch -d` 又 `touch`，把 mtime 改回现在 |
| **服务器没有 `sqlite3` 命令行** | — | 用 Python `sqlite3` 模块（还能顺便做 integrity check） |
| **中文时间格式** | `page.jsx` / `history` | 后端返回 ISO（带 `T`），显示前 `replace("T"," ")` 再截 |
| **headless Chrome 要 `--user-data-dir`** | — | 否则报 `Failed to create headless user data directory container`；建议再加 `HOME=/tmp`，避免钥匙串/崩溃上报 |
| **headless Chrome 最小视口 500px** | — | 390 宽截图不能判断窄屏溢出；要在页面里量 `innerWidth/scrollWidth` |
| **PDF 里的康熙部首字符** | `verify_rules.py` | `⻛/⻝/⻓` 与「风/食/长」码位不同；不映射永远匹配不上 |
| **端口被旧服务占用** | 本机 8000/8010/4321 | 先 `lsof` 看清楚是谁的，**别想当然 kill** |
| **Markdown 图片相对路径** | `docs/PRD.md` | 备忘录/飞书不认相对路径；交付用 `docs/PRD.pdf`，本地预览用 `docs/PRD.html` |
