# UI 风格落地说明（基于 Notion 风格参考）

> 输入：`DESIGN.md`（Notion 风格参考，营销站体系）
> 状态：**待补 4 类参考后定稿**；本文件说明"哪些能用、哪些要改、还缺什么"
> 原则：**保留它的气质，改造它的语法。** 营销页的色彩法则不能直接搬进高密度工作台。
>
> ⚠️ 本文件是**设计分析**，文中 `#f6f5f4` 等是参考稿原值。**最终落地令牌以 `frontend/app/globals.css` 为准**：`--paper #FFFAF0`、`--surface #FFFDF7`、红蓝增删（ADR-005）。

## 1. 这份参考是什么

一句话：**暖纸质感 + 单一蓝色主操作 + 用彩色卡片做节奏 + 发丝级描边 + 无阴影无渐变。**

核心可迁移的 5 条：

1. 画布用暖白 `#f6f5f4`，卡片用纯白 `#ffffff` —— **这个层级不能反**
2. 主操作只有一种颜色（蓝 `#0075de`），其余动作一律 ghost / text
3. 分隔靠 **1px 描边 `rgba(0,0,0,.08)`**，不靠阴影
4. 文字层级靠**同一个黑色的透明度**（100/95/60/40），不是靠加新颜色
5. 圆角只有两档：卡片 12px、按钮 8px；胶囊 9999px 只给标签

这 5 条我全部接受，并且它们恰好解决了我们"工具型高密度"的两个难题：**怎么在不加线条和阴影的情况下分区**、**怎么让彩色不干扰阅读**。

## 2. 必须改造的三处（营销页 → 工作台）

| 参考里的做法 | 为什么不能直接用 | 我们的改法 |
|---|---|---|
| 巨型标题 54–96px、负字距 -2~-4.6px | 工作台最长的一行标题是 22px；96px 根本用不到 | **不用 display 档**；最高只到 22px（面板标题）/ 28px（页面标题）。负字距只用在 ≥24px 的拉丁字符 |
| 区块间距 80px、卡片内边距 24px | 80px 是营销页的呼吸；工作台会让一屏信息量掉一半 | 区块间距 16–24px，卡片内边距 16–20px；**密度档从 comfortable 改为 compact** |
| 大面积彩色卡片（黄/珊瑚/天蓝）铺满页面 | 在营销页是"节奏"，在编辑器里会**抢夺文字注意力**，且与严重度颜色冲突 | **把彩色收进 3 个地方**：入口页背景块、空态/结果摘要卡、统计卡片。**工作台三栏保持近单色** |

### 一条容易被忽略的 CJK 规则

参考里的负字距是为拉丁字母设计的。**中文不要套用**——中文字面本就方正，再加负字距会粘在一起。

- 拉丁：≥24px 可用 `-0.02em ~ -0.03em`
- 中文：一律 `0`，最多 `-0.01em`
- 中英混排：把字距加在包含拉丁的节点上，不要加在整段

### 3.1 直接沿用

| 用途 | 值 |

| 页面画布 | `#f6f5f4` |
| 面板/卡片 | `#ffffff` |

### 3.2 改写

| 用途 | 参考 | 我们 |
|---|---|---|
| 面板分区 | 卡片浮在画布上 | 三栏**平铺**，用 1px 竖线分隔，不做卡片投影（工作台不是卡片流） |

| 正文字宽 | 无限制 | 单栏 ≥34 字、≤42 字（约 560–700px），超了加内边距 |

## 4. 色彩纪律（这是"多元但不像 AI slop"的关键）

参考最值钱的一句是：**"#0075de 是唯一的填充按钮颜色，色彩多样性属于卡片背景"**。

翻译到工作台：

| 位置 | 允许的颜色 |
|---|---|
| 入口页 | 暖纸底 + 一张彩色卡片（黄或珊瑚）+ 蓝色主按钮 |
| 工作台 | 近单色：纸 / 白 / 墨 + **仅**严重度色 + 高亮色 + 主按钮蓝 |
| 历史页 | 单色 + 状态标签色 |
| 规则页 | 单色 + 三档状态色（verified/official/pending） |
| 空态/结果摘要 | 可放 1 张彩色卡片（这是"创造性"的出口） |

**禁止**：给每个面板换底色、用彩色区分三栏、在列表里用渐变、给卡片加阴影。

## 8. 参考素材评估（2026-10-25 收到）

### 8.1 已收到的 5 份

| # | 素材 | 能借什么 | 借不到什么 |
|---|---|---|---|
| 1 | Notion 工作区（左导航 + 表格页） | **表头/行高/胶囊标签**的表格样式（历史页直接用）；侧栏宽度约 9%（230px）；顶栏 44px；浅灰侧栏 + 纯白主区 | 右侧批注面板（这张没有） |
| 2 | Linear Issues 列表 | 列表页的克制感：**行高 52、无分隔线、hover 才显操作**；顶栏 48 | 详情页（issue 右栏没拍到） |
| 3 | Postman 首页 | **三栏比例的实证**：约 23% / 52% / 25%；右栏"Needs your attention"就是"待处理面板"的形态 | 它是首页，不是编辑器；右栏是空态卡片 |
| 4 | 中文文档页（学习笔记） | **中文正文的排版事实**：正文约 19px / 行高 1.75；蓝色圆点列表；暖橙高亮块；标题层级克制 | 它是文档页，不是应用界面 |
| 5 | RStudio 深色 diff | 删除行的**红底 + 左侧红竖条**；行级高亮而非字符级 | 没有"新增"的样式；深色底不适用 |

### 8.2 最重要的发现：你喜欢的那套"多元"，在 Notion 的工作界面里其实是收敛的

对比一下：

- **Notion 营销页**（DESIGN.md 描述）：暖纸底 + 大黄/珊瑚卡片 + 96px 标题 → 色彩很"多元"
- **Notion 工作界面**（图 1）：浅灰侧栏 + 纯白主区 + 一个蓝色小按钮 → **几乎没有颜色**

这正好印证我们的改造原则：**入口页给色彩，工作台给克制**。图 1 就是我们工作台的正确参照，不是 DESIGN.md 里的营销页。

### 8.3 还缺的那一张（方向性）

三张"三栏"其实都不是我们的核心形态：

- Notion = 导航 + 列表
- Linear = 导航 + 列表
- Postman = 导航 + 首页 + 空态面板

**没有一张是「一段可编辑的正文 + 右侧逐句批注」。** 而这恰恰是我们产品最核心的屏幕。

最贴近的真实产品不是 Notion/Linear，而是**写作校对工具**：

- **Grammarly**（编辑器内划线 + 右侧 suggestion 卡）
- **秘塔写作猫 / 火龙果写作**（中文，粘贴文本 → 逐句标错 → 右侧建议）
- **GitHub PR 的行内评论**（代码行 → 右侧评论，定位方式）

> 这一张补上，工作台的"批注如何与正文对齐"就有实证；不补也能做，但那是我的设计判断，不是参考。

### 8.4 diff 的结论需要澄清

原始回复写的是「删增就用红色标注出来好了」，配图（RStudio）只演示了**删除**。

风险：删和增都用红，用户分不清"哪句是原来的、哪句是新的"。三个方案：

| 方案 | 删除 | 新增 | 优点 | 缺点 |
|---|---|---|---|---|
| **A（推荐）** | 红底 + 删除线 | 绿底 + 下划线 | 一眼分清 | 引入绿色（参考调色板里没有） |
| B | 红底 + 删除线 | 红下划线 + 左红条 | 只用红，符合偏好 | 色弱用户只能靠线条区分 |
| C | 只标"改过" | 同左 | 最简 | 看不出改成了什么，信息量不足 |

### 8.5 ④ 风险标记"先不考虑"的处理

不找参考，但**不能只靠颜色**这一点用零成本方式兜住：每个严重度都带**文字标签**（高危 / 中危 / 低危）+ **形状不同的图标**（实心三角 / 空心三角 / 短横）。这样色弱用户也能读，且不需要额外素材。

### 8.6 开放决定

- diff 用 A / B / C？
- 图标：Lucide（一致、开源）还是不用图标、纯文字 + 符号？
- 空态是否用一张彩色卡片（图 3 的右栏就是很好的空态范式）？

## 9. 收到第二份素材后的结论（2026-10-25）

### 9.1 雅思批改工具 = 我们最接近的形态（缺口已补）

素材：左栏作文带**黄色/绿色下划线**、行内小图标（💬 / 👍）；中栏"批改 20"卡片（Good Point / Suggestion，含原文片段 + 解释 + 翻译）；右栏评分与总评。

可直接借用：
- **下划线标问题**（而不是整块底色），正文可读性不受损
- 行内小标记 + 右侧卡片一一对应
- 卡片结构：类型 → 原句片段 → 解释 → 建议

不借：它的右栏是"评分"，我们的是"改写后的全文"。

### 9.2 ⚠️ 一个必须纠正的事实：DESIGN.md 里没有绿色

原始调色板只有：蓝(`#0075de`/`#097fe8`/`#62aef0`/`#e6f3fe`)、暖纸、黑白灰(`#757575`/`#615d59`/`#696969`)、黄(`#ffb110`/`#e89d01`)、珊瑚红(`#f64932`/`#e32d14`)、棕(`#b18164`)、深蓝(`#02093a`)。

**没有绿色。** 所以"红色和绿色都用 DESIGN.md 色号"这条执行不了——绿色必须外挂，会破坏"全用文档色"的初衷。

### 9.3 建议：用「红 + 蓝」做增删，而不是「红 + 绿」

| | 删除 | 新增 |
|---|---|---|
| 颜色 | `#e32d14`（vermillion，文档内） | `#0075de`（notion blue，文档内） |
| 底 | `#fdeceb` | `#e6f3fe`（sky tint，文档内） |
| 线 | 删除线 | 下划线 |

三个理由：
1. **全部来自 DESIGN.md**，满足"风格统一"的要求；
2. **红蓝对色弱友好**（红绿色盲是最常见类型，红蓝是安全组合）；
3. 蓝色本来就是系统的主强调色，用它表示"新的、改好的"顺理成章。

若坚持"红绿"的行业惯例，就需要新增一个绿（如 `#067647`/`#e7f6ec`），并接受它不在参考文档里。

### 9.4 严重度：颜色 + 线型双编码

| 级别 | 下划线 | 底色 | 标签（中栏） |
|---|---|---|---|
| 高危 | 实线 2px `#e32d14` | `#fdeceb` | 红底白字「高危」 |
| 中危 | 实线 1.5px `#e89d01` | `#fdf6e3` | 琥珀底黑字「中危」 |
| 低危 | 虚线 1px `#757575` | 无 | 灰底黑字「低危」 |

理由：「红色深浅」三档肉眼几乎分不出（尤其不同屏幕），必须加线型差异；真正的规则信息放在中栏卡片里，左栏只负责"这里有东西"。
