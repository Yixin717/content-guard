# UI 结构说明（v1 · 待配图细化）

> 状态：结构已定，视觉待参考图确定后细化
> 依据：ADR-001（检查是内核）、ADR-002（双入口、检查为主路径、不做营销落地页）
> 原则：**先定结构，再定皮肤。** 本文件只回答"有什么、在哪、什么时候出现"，不回答"什么颜色、什么圆角"。

---

## 0. 一句话

> 商家把要发的文案贴进来 → 右边告诉你哪句会出事、违反哪条 → 点一句就能看条款原文 → 一键改成合规版本 → 人工确认后导出。

---

## 1. 页面地图

只有 3 个页面，全部为桌面优先（1440 宽设计，≥1280 可用）。

| 页面 | 路由（前端内部状态） | 作用 | 优先级 |
|---|---|---|---|
| **入口页** | `/` | 粘贴文案 / 选择生成 / 看最近记录 | P0 |
| **工作台** | `/workbench` | 检查 → 引用 → 改写 → 确认（核心） | P0 |
| **历史** | `/history` | 已确认文案 + 审计信息 | P1 |
| **规则** | `/rules` | 规则列表 + 搜索 + 评测摘要 | P1 |

> 不做：营销落地页、登录页、设置页、定价页。

## 2. 入口页（首屏）

```
┌────────────────────────────────────────────────────────────┐
│  Content Guard          规则 40 条 · 依据《广告法》与小红书规范 │ 48px 顶栏
├────────────────────────────────────────────────────────────┤
│                                                            │
│              发布前，先过一遍                                 │ 28px 标题
│         把要发的文案贴进来，我告诉你哪句会出事                  │ 15px 副标题
│                                                            │
│         ┌──────────────────────────────────────────┐       │
│         │                                          │       │
│         │   （多行粘贴区，10 行高，monospace 不强制）  │       │
│         │                                          │       │
│         └──────────────────────────────────────────┘       │
│         平台 小红书 ▾        已粘贴 218 字   [ 开始检查 → ]    │
│                                                            │
│         还没有文案？让 AI 先写一版 →                           │ 次要入口（一行字）
│                                                            │
│  ──────────────────────────────────────────────────────    │
│  最近                                                        │
│  · 冰丝阔腿裤   3 条违规   10/24 17:20                       │
│  · 皮夹克探店   1 条违规   10/24 15:12                       │
└────────────────────────────────────────────────────────────┘
```

**规则**
- 粘贴框是唯一视觉重心；不放功能介绍、不放插画、不放"三大特性"。
- 字数为 0 时，「开始检查」置灰；>5000 字提示"过长，建议分段检查"。
- 平台切换目前只有"小红书"，做成下拉但是禁用态 + 提示"更多平台规划中"（诚实，不假装支持）。
- 「让 AI 先写一版 →」点击后进入同一页的生成形态：粘贴框替换为卖点表单（商品名 / 卖点 / 价格 / 语气），按钮变为「生成 3 版」。

## 3. 工作台（核心）

### 3.1 布局

三栏 + 顶部流程条。左栏生成/检查后**可折叠为 56px 图标条**。

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 输入  › ② 检查  › ③ 改写  › ④ 确认        [ 导出 ]  ← 主按钮       │ 48px
├─────────┬──────────────────────────────────────┬─────────────────────┤
│ 来源 300 │  正文 740                             │ 判定 400             │
│(折叠 56) │                                      │                     │
│         │  【痛点型】【场景型】【促销型】  ← 仅生成模式 │ 3 条 · 高危 2        │
│ 粘贴文本 │  ─────────────────────────────       │ ───────────────      │
│ 或卖点   │  《标题》                             │ ● 高 FLM-001         │
│         │  口播脚本正文……                        │   三天根治痘痘        │
│ [重新检查]│                                      │   切除 · 看条款 ›    │
│         │  ─────────────────────────────       │ ● 高 ABS-004         │
│ ──────  │  卖点：遮胯 / 69 两条                  │ ○ 中 PLT-020         │
│ 历史 3 条 │  AI 声明：本内容由 AI 辅助生成…        │ ───────────────      │
│         │                                      │ 待确认 1 · 疑似 1     │
└─────────┴──────────────────────────────────────┴─────────────────────┘
```

**宽度**：左 300（折叠 56）/ 中 flex（≥560）/ 右 400。1440 下中栏 740；左栏折叠后中栏 1040。
**分隔**：1px 线，不用阴影；右栏可拖拽调宽（可选，P2）。

### 3.2 两种模式，同一套布局

| | 检查模式（主） | 生成模式（次） |
|---|---|---|
| 左栏 | 原文（可编辑）+ 字数 + 平台 | 卖点表单（商品名/卖点/价格/语气） |
| 中栏 | 一段文本，**行内高亮违规句** | 3 版草稿 tab（痛点/场景/促销），切 tab 不重生成 |
| 右栏 | 违规列表（可能多条） | **覆盖说明**（不得留空，见 3.4） |
| 主按钮 | 「按问题改写 →」 | 「用这版改写 →」 |

### 3.3 右栏的三种内容

**① 有违规**：列表，按严重度排序（高→中→低）。

```
● 高   FLM-001  非医疗商品禁止涉及疾病治疗功能
      「三天根治痘痘」
      《广告法》第十七条 · 置信度 0.95        [ 查看条款 › ]
```

**② 无违规**（必须说清"查了什么"）：

```
✓ 已核 40 条规则，未发现明确违规

需人工确认：
· 商品资质（材质/成分是否与描述相符）
· 账号报备（是否走品牌合作报备）
· 图片与视频（本次仅检查文本）
```

**③ 检查失败**：不显示"通过"，显示错误 + 重试：

```
⚠ 检查未完成（模型超时）
  本次结果不可作为发布依据                     [ 重试 ]
```

### 3.4 生成模式右栏的硬性要求

生成模式下即使 0 违规，右栏也不能空，必须显示：

> 已核 40 条规则，未发现明确违规
> **但这不等于可以发**：AI 生成的内容仍可能被平台判定违规（平台还会看账号、图片、上下文）。以下需人工确认：商品资质 / 账号报备 / 图片视频。

理由：空白会让用户以为"没检查"。

### 3.5 四种状态

| 状态 | 中栏 | 右栏 |
|---|---|---|
| 空（未检查） | 显示原文，提示"检查后会在这里高亮问题句" | 空态插画位 + 一句提示 |
| 检查中 | 保持可读，顶部细进度条（不用整页 loading） | 骨架屏 3 条 |
| 有结果 | 违规句高亮 + 侧边标记 | 列表 |
| 失败 | 原文不变，顶部错误条 | 错误 + 重试 |

## 4. 批注模型（核心交互）

**这是产品和竞品的分水岭，必须做扎实。**

### 4.1 锚定

- 每条违规带 `quote`（原文片段），前端在正文里**定位第一个匹配位置**并加高亮。
- 多个违规落在同一句 → 该句只高亮一次，但右栏显示多条，点击时高亮相应段落。
- 找不到匹配（理论上被后端过滤了，前端仍兜底）→ 该条只在右栏显示，不画高亮，并加"定位失败"小标记。

### 4.2 交互

| 动作 | 结果 |
|---|---|
| 鼠标悬停右栏违规项 | 正文对应句加浅色描边（不弹窗） |
| 点击违规项 | 正文滚动到该句 + 该句加深高亮；右栏该项选中态 |
| 点击「查看条款」 | **抽屉从右滑出，宽 480，覆盖右栏**（正文保持可见） |
| 抽屉关闭 | 点遮罩 / Esc / 右上关闭 |
| 悬停正文高亮句 | 显示小浮层：规则名 + "查看条款" |

### 4.3 抽屉内容（这是"可追溯"的实体）

```
┌──────────────────────────────────────┐
│ FLM-001                      [×]     │
│ 非医疗商品禁止涉及疾病治疗功能          │
│ ──────────────────────────────────── │
│ 判定依据                               │
│ 《广告法》第十七条                      │
│ 「除医疗、药品、医疗器械广告外，禁止其   │
│   他任何广告涉及疾病治疗功能……」        │
│ 查看官方原文 ↗ · 抓取于 2026-10-23      │
│ ──────────────────────────────────── │
│ 你的原文                               │
│ 「三天根治痘痘」                        │
│ ──────────────────────────────────── │
│ 建议改写                               │
│ 我用了两周，脸上没那么油了…             │
└──────────────────────────────────────┘
```

**必须包含**：规则原文（不是模型转述）、出处、抓取时间、你的原文、建议。
**必须诚实**：`platform_pending` 的规则显示"该条依据待补齐原文"角标，不装作和法条一样硬。

## 5. 改写与 diff

### 5.1 入口

- 检查模式：「按问题改写 →」（有违规才可点）
- 生成模式：「用这版改写 →」

### 5.2 改写后的中栏

中栏顶部出现三段式切换：**原文 | 改写 | 对比**

对比视图：句子级 diff（不是字符级），删除句标红+删除线，新增句标绿，未变句正常。

```
对比
  ~~全网最低价！~~                     ← 删除（红、删除线）
  活动期间价格很划算，比平时便宜一些。     ← 新增（绿）
  我用了两周，脸上没那么油了。           ← 保留（正常）
```

### 5.3 改写结果必须显示"复检"

```
改写：4 条 → 0 条（下降 100%，共 2 轮）      ← 来自 API 的 after_violations / rounds
```

若仍有剩余违规：红字提示"仍有 N 条未解决，建议人工处理"，并列出。

### 5.4 事实保护提示

diff 中若检测到**价格/规格/时间**等数字被改动，加一条醒目提示：

> ⚠ 改写动到了价格数字（69 → 两条 69），请人工确认

## 6. 确认与导出

- 「确认并导出」是**唯一的绿色/主按钮**，位置固定在顶栏右侧。
- 点击后弹确认层：展示最终全文 + 一句「确认后本次修改会被记录（审计），不可自动发布」。
- 确认成功 → 显示审计 id + 「复制文案」「下载 .txt」「再检查一次」。
- 已确认的文案再次进入 → 显示"已确认（10/24 17:26）"，按钮变为「重新确认」。
- **不提供"一键发布"**，永远没有。

## 11. 与现有 API 的映射

| UI 区块 | 接口 | 字段 |
|---|---|---|
| 规则计数（顶栏） | `GET /health` | `rules` |
| 检查模式提交 | `POST /api/check` `{content}` | → `violations[] / uncertain[] / suspected[] / human_review / reason` |
| 生成模式 | `POST /api/generate` `{brief, tone}` | → `drafts[]` |
| 检查草稿 | `POST /api/check` `{draft_id}` | 同上 |
| 改写 | `POST /api/rewrite` `{draft_id}` | → `changes[] / before_violations / after_violations / rounds` |
| 确认 | `POST /api/confirm` `{draft_id, final_content, reviewer}` | → `audit_id / idempotent` |
| 历史 | `GET /api/history?limit=20` | `items[]` |
| 规则页 | `GET /api/rules?category=` | `items[]` |

### ⚠ 两个已知的接口缺口（前端开工前要补）

1. **检查模式没有 draft_id**：`POST /api/check {content}` 现在只返回结果，但 `POST /api/rewrite` 只接受 `draft_id`。
   → 需要让 check 在传入纯文本时**自动建一条 draft**（`source=paste`）并返回 `draft_id`，否则粘贴模式的"按问题改写"点不动。
2. **规则页缺三档统计**：`/api/rules` 只返回列表，没有 `verified/platform_official/platform_pending` 的计数。
   → 前端可自行统计（列表里带 `status`），不必改接口。

## 14. 修订 v2（2026-10-25）：三栏语义改为「原文 | 诊断 | 改写」

参考素材：雅思作文批改工具（左正文带下划线 → 中批改卡片 → 右总评），见 `docs/ui-style.md` §9。

### 14.1 新的三栏语义

| 栏 | 内容 | 依据 |
|---|---|---|
| **左 500** | 原文，**可编辑**；违规处用下划线 + 编号标出（①②③） | 参考的"正文 + 下划线" |
| **中 400** | 诊断卡片列表：编号、严重度、`rule_id`、条款原文（可展开）、为什么、建议 | 参考的"批改卡片" |
| **右 444** | **改写后的全文**，与左侧逐句对应；改动处用颜色标出 | 参考的"评分/结果面板"，我们换成"处方" |

一句话：**左「现在是什么样」→ 中「为什么不行」→ 右「改成什么样」。**

### 14.2 由此带来的两个简化（重要）

1. **去掉"条款抽屉"**：条款原文在中栏卡片内联展开即可。少一个浮层、少一套状态、少一个 480px 组件。
2. **去掉"字符级 diff 视图"**：左原文 / 右改写**并排本身**就是 diff。不需要把两段文字塞进一栏再做对比。

> 少这两个组件，D5 的前端工作量至少省一天，而且交互更直白。

### 14.3 编号体系

- 每条违规一个编号（①②③…），**三栏共用同一编号**：左栏下划线右上角标号、中栏卡片标题、右栏改动处。
- 编号顺序 = 严重度排序（高→中→低），不是文本顺序。
- 点击任一栏的编号 → 三栏同步高亮并滚动到对应位置。

### 14.4 改写未完成时右栏显示什么

右栏不能空。改写前显示一张卡：

```
┌───────────────────────────┐
│ 3 条高危待处理             │
│ [ 一键全部改写 ]           │
│                           │
│ 或逐条：在中间卡片点"改这条"  │
└───────────────────────────┘
```

### 14.5 一个必须守住的不变量

改写后，**没有被标记的句子必须逐字不变**。前端可以做一次自检：
逐句比对左/右，若发现未标号句子被改动 → 在右栏顶部提示"改写动到了未标记内容，请人工核对"。

这条能同时防住模型"顺手润色"和"改出新违规"，也是面试时的好细节。

### 14.6 宽度

1440 下：左 420 / 中 600 / 右 420。1280 下等比压缩，<1024 单列堆叠。

## 15. 修订 v3（2026-10-25 · 第一轮原型反馈后）

| 反馈 | 改法 |
|---|---|
| 底色太白 | 画布 `#f3eee6`、面板 `#fdfbf7`，描边改为暖调 `rgba(60,40,20,.10)`；条款块 `#f7f2ea` |

- 无违规态：右栏不再是一句空提示，改为「可以发布」卡（含资质/报备/AI 标注提醒 + 复制正文）。

## 16. 修订 v4（2026-10-25 · 第二轮原型反馈）

| 反馈 | 改法 |
|---|---|
| 中间太宽 | 从 `380 / 1fr / 380`（中 676）改为 **`420 / 1fr / 420`**（中 600）：中栏仍最宽，但不再是"空旷"的感觉 |
| 左边字太小、太窄 | 正文 **16px → 17px**，行高 1.85；左栏内边距 20 → 22 |
| 左右字号必须一致 | 抽成两个变量 `--doc-size` / `--doc-line`，**原文区与改写区共用**，杜绝以后一边改一边忘 |

> 用变量而不是写死两处，是因为"左右对齐"是这类双栏产品最容易退化的地方：今天改左边、明天改右边，一周后就对不上了。

## 17. 修订 v5（2026-10-25 · 入口页的第二入口）

**问题**：原来「还没有文案？让 AI 先写一版 →」是 13px 的纯文本链接，压在 720px 粘贴框下面，几乎没有存在感；点下去也只是切一个样本，不像一条真实的路。

**改法**

1. **从文字链改成 ghost 按钮**：`还没有文案？ [生成一版 →]`，13.5px、浅蓝底，**右对齐到主按钮同一条竖线**，读作"另一个动作"而不是脚注。
2. **文案去掉"AI"**：只写「生成一版」。产品卖的是"能发"，不是"用了 AI"。
3. **第二入口变成真流程**：点进去是生成表单（卖什么/卖给谁、价格与活动、语气三选一），按钮「生成 3 版」，生成完直接进工作台。顶栏步骤同步显示「生成」而不是「粘贴」。

**为什么不做成两张等权大卡**：那会让用户站在首页先做一次"选择"，而 ADR-002 要求检查是默认动作；ghost 按钮在视觉上明确是次选，但位置和尺寸都够被看见。
